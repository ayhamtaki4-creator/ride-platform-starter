# التعامل مع بدء تشغيل Render Free — طريق الشام

## المشكلة

تستخدم خدمة `ride-platform-starter` (NestJS API) خطة Render Free.
بحسب وثائق Render الرسمية، تتوقف خدمة الويب بعد 15 دقيقة من دون
طلبات وتحتاج نحو دقيقة لبدء العمل مجددًا:
https://render.com/docs/free

خلال فحص إنتاج بتاريخ 2026-10-14 ظهر أول طلب `/api/health` بعد
قرابة 72 ثانية من الخمول؛ وبعد بدء الخادم، استجابت نقاط API الأخرى
بسرعة ملحوظة. هذا **تأخير في الاستضافة** وليس خللًا في قاعدة البيانات.

## تحسين تجربة الزائر دون تكلفة جديدة

1. يبدأ المتصفح إرسال **GET واحد متدرّج** إلى `/api/health` بمجرد دخول
   الصفحة العامة على Cloudflare؛ لا ينتظر ظهور الصفحة أو الضغط على «احجز».
2. يُشارك الاستدعاء الجاري ضمن التبويب نفسه، ولا يكرر الإيقاظ إذا تم
   تأكيد صحة الخادم حديثًا. لا توجد مهام مجدولة أو ping دائم لإبقاء
   الخادم حيًا.
3. على صفحة الحجز، تُعرض رسالة تحميل أثناء انتظار الخادم (وبعد أربع
   ثوانٍ تظهر ملاحظة احتمال استيقاظ Render)، ثم تُجلب المسارات والأسعار
   بعد نجاح فحص الصحة.
4. إذا تعذّر تحميل المسارات، يظهر زر **إعادة محاولة تحميل المسارات** دون
   مسح بيانات العميل. لا تُعاد طلبات الحجز POST تلقائيًا منعًا لتكرارها.
5. بعد تجاوز الخمول يُنهي الإيقاظ المحاولات خلال 100 ثانية بدل
   انتظار غير محدود.

## حدود الحل

- هذا التحسين لا يمنع إيقاف Render Free بعد 15 دقيقة خمول.
- إذا فتح زائر رابط الحجز مباشرةً بعد فترة خمول، فقد يظل هناك انتظار
  أثناء إعادة تشغيل الخادم. أما زيارة الرئيسية أولًا فقد تبدأ الإيقاظ
  مبكرًا قبل إتمام معلومات الحجز.
- للاستجابة الفورية بشكل مستمر يلزم **تغيير خطة Compute للخدمة نفسها
  إلى خطة مدفوعة** بعد مراجعة تكلفة الاشتراك مع المالك.
- لا تستخدم GitHub Actions أو خدمة ping خارجية كل بضع دقائق لإبقاء
  الخادم مفتوحًا؛ يمكن أن تستهلك رصيد الساعات المجانية وأن تعطي
  انطباعًا زائفًا بأن الخطة المجانية تضمن استجابة فورية.

## التحقق

- اختبار الصفحة العامة يبدأ `GET /api/health` دون حظر التنقل.
- اختبار تأخر `/api/health` لمدة قرابة 5 ثوانٍ يُظهر حالة «جارٍ تشغيل
  خدمة الحجز» ولا يعرض «لا توجد مسارات» خطأً.
- بعد عودة صحة الخادم، تظهر خيارات الخطوط.
- فحوصات الإنتاج الحالية تختبر صحة API وRedis وNeon والدومين الرسمي،
  لكنها لا تُنشئ حجزًا حقيقيًا تلقائيًا.
